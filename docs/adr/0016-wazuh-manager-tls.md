# ADR 0016: Wazuh manager TLS to the indexer

- Status: Accepted
- Date: 2026-10-21
- Related: issue #94, ADR 0013, ADR 0014, ADR 0015, ADR 0017

## Context

ADR 0015 verified that the indexer serves HTTPS with a certificate whose only
subject alternative name is `DNS:wazuh-indexer.local`. The manager image ships
filebeat, and the official `wazuh-docker` 4.9.0 model configures it from
environment variables (`INDEXER_URL`, `FILEBEAT_SSL_VERIFICATION_MODE`,
`SSL_CERTIFICATE_AUTHORITIES`, `SSL_CERTIFICATE`, `SSL_KEY`) through the image
init script `1-config-filebeat`. The manager hop to the indexer was still
plaintext.

The corrected `opensearch.yml` copy initially lacked
`plugins.security.allow_default_init_securityindex`, so the security index was
never created and the indexer ran unsecured. ADR 0015 records that correction;
the flag is now part of the copy.

## Decision

1. Manager TLS lives only in the opt-in overlay
   `shallot-infra/compose.wazuh-tls.override.yml`. The plain baseline in
   `compose.wazuh.yml` keeps `INDEXER_URL=http://wazuh-indexer:9200`.
2. `INDEXER_URL=https://wazuh-indexer.local:9200` with
   `FILEBEAT_SSL_VERIFICATION_MODE=full`, so hostname and chain verification
   stay enabled. The indexer service gets the compose network alias
   `wazuh-indexer.local` so the certificate name resolves on the network. No
   certificate is regenerated.
3. The manager trusts only the lab CA and presents the lab manager
   certificate. The overlay mounts the official `wazuh-certs-tool` input
   layout read-only under `/etc/ssl`: `root-ca.pem` to
   `/etc/ssl/root-ca.pem`, `filebeat/filebeat.pem` to
   `/etc/ssl/filebeat.pem`, and `filebeat/filebeat-key.pem` to
   `/etc/ssl/filebeat.key`. The image init script reads those paths from
   `SSL_CERTIFICATE_AUTHORITIES`, `SSL_CERTIFICATE` and `SSL_KEY`.
4. The manager authenticates to the indexer as the least-privilege `filebeat`
   user, not as `admin`. Shipping alerts needs write access to `wazuh-*` and
   nothing else, and the shipping path must not depend on an administrator
   credential. The `filebeat_writer` role is granted by username in
   `roles_mapping.yml` and the role itself is write-only to `wazuh-*`.
5. The `filebeat` password is generated by the repository bootstrap script
   (`ansible/scripts/bootstrap_wazuh_credentials.py`) and written to the
   git-ignored `.env` as `WAZUH_FILEBEAT_PASSWORD`, mode 0600. The overlay
   fails fast with `:?WAZUH_FILEBEAT_PASSWORD is required` when the bootstrap
   has not run, so a fresh checkout cannot start with an implicit credential.
6. Input layout: `root-ca.pem`, `indexer.pem`, `indexer-key.pem`,
   `admin/admin.pem`, `admin/admin-key.pem`, `filebeat/filebeat.pem`,
   `filebeat/filebeat-key.pem`.
7. The manager service runs with `userns_mode: keep-id` and
   `cap_add: CHOWN, SETUID, SETGID, DAC_OVERRIDE, FOWNER, SYS_CHROOT, KILL`
   over `cap_drop: ALL`. The image init copies the permanent data into the
   volumes and chowns it to the `wazuh` user, the daemons chroot to
   `/var/ossec`, and `wazuh-control` checks the daemons with `kill -0`, so
   `KILL` is required. Without them the manager init aborts with
   `wazuh-apid did not start correctly` and no daemon runs.

## Verification boundary

Static checks need no container and no credential:

1. `pytest tests` passes.
2. `python3 ansible/scripts/check_runtime_policy.py` passes.
3. `podman-compose -f compose.yml -f compose.wazuh.yml
   -f compose.wazuh-tls.override.yml --profile wazuh-secure config` resolves
   the merged manager environment and mounts.
4. Secret scan finds no key material in the diff; `git diff --check` is clean.

Runtime starts are separate, each under explicit human approval, and limited
to the indexer and the manager. The runtime evidence below was produced that
way on 2026-10-21.

## Runtime evidence

Verified on 2026-10-21, rootless Podman, indexer and manager only, explicit
human approval, credentials generated by the repository bootstrap script
(mode 0600, never printed):

1. The image entrypoint does not create the security index, so the corrected
   `opensearch.yml` now carries
   `plugins.security.allow_default_init_securityindex: true`. The index
   `.opendistro_security` is created from the mounted
   `internal_users.local.yml`; cluster health GREEN, admin login with the
   generated password returns 200.
2. Certificate staging: the wrapper staged the five files into
   `/usr/share/wazuh-indexer/certs`, public material 0644, private keys 0600,
   owner `1000:1000`.
3. The network alias resolves: from the manager container
   `wazuh-indexer.local` resolves to the indexer, and `openssl s_client` with
   the lab CA and the manager certificate returns
   `Verify return code: 0 (ok)` against server certificate
   `CN=wazuh-indexer.local`.
4. The image init script applied the official environment contract:
   `hosts: ['https://wazuh-indexer.local:9200']`, `ssl.verification_mode: 'full'`,
   CA `/etc/ssl/root-ca.pem`, client certificate `/etc/ssl/filebeat.pem`.
5. A request from inside the manager container to
   `https://wazuh-indexer.local:9200` with the manager certificate and the
   admin credentials returned 201 on a document write, 200 on search, and 200
   on index delete. The same request to `https://wazuh-indexer:9200` failed
   with `CERTIFICATE_VERIFY_FAILED` hostname mismatch, so hostname
   verification is enforced.
6. Filebeat published the manager alerts over that hop as the least-privilege
   `filebeat` user:
   `Connection to backoff(elasticsearch(https://wazuh-indexer.local:9200)) established`,
   and the indexer holds `wazuh-alerts-4.x-2026.10.21`.

## Follow-ups

- The manager `ossec.conf` monitors almost nothing; the official single-node
  model mounts a fuller `wazuh_manager.conf`.
- Agent enrollment, the agent port mapping and the rootless UID mapping are
  recorded in ADR 0017.

## Rollback

Revert the overlay, base overlay, and ADR commits. Remove the local input
directory copy. No committed credential is touched.

## Consequences

- The manager hop is encrypted and hostname-verified; the indexer name is now
  part of the contract between certificate and network configuration.
- The plain HTTP baseline remains available for the non-TLS development path.
- The shipping path needs only a write-only credential, so a compromised
  manager container cannot read the indexer.
- If the indexer rejects the unmapped manager certificate DN, drop
  `SSL_CERTIFICATE` and `SSL_KEY`; the init script then leaves the client
  certificate settings unset and the manager trusts the CA only.
